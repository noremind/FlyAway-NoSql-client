# FlyAway Client

Nuxt 3 клиентская часть платформы FlyAway. Здесь находится только фронтенд: страницы, компоненты, Pinia store, middleware, layout и UI-логика. Backend API живет отдельно в `FlyAway-server`.

## Стек

- `Nuxt 3`
- `Vue 3`
- `Pinia`
- `PrimeVue`
- `SCSS`
- `@nuxtjs/i18n`
- `Swiper`
- `Yandex Maps API`

## Локальный запуск

1. Установить зависимости:

```bash
npm install
```

2. Создать локальный env-файл:

```bash
cp .env.example .env
```

3. Указать локальный backend:

```env
NUXT_DEV_API_TARGET=http://localhost:3001
```

4. Запустить клиент:

```bash
npm run dev
```

По умолчанию Nuxt будет доступен на `http://localhost:3000`.

## Переменные окружения

Смотри [.env.example](./.env.example).

Важно:

- не коммитить `.env`;
- не хранить приватные ключи во фронтенде;
- `NUXT_PUBLIC_YANDEX_MAPS_API_KEY` является публичным browser key;
- `SERVER_URL` должен содержать `/api` для production API.

## Связь с backend

Клиент ходит в backend через API base URL:

- локально: `NUXT_DEV_API_TARGET`, например `http://localhost:3001`;
- production: `SERVER_URL`, например `https://api.example.com/api`.

Основные запросы выполняются через `useApi`, `useFetchClient` и `useFetchSsr`.

## Роли

### guest

Неавторизованный пользователь.

Может:

- смотреть главную страницу;
- искать туры и отели;
- открывать карточки и детальные страницы;
- смотреть партнеров;
- открыть auth modal при попытке добавить тур в избранное или забронировать.

Не может:

- добавлять в избранное;
- бронировать туры;
- открывать личный кабинет;
- открывать admin panel.

### user

Обычный авторизованный пользователь.

Может:

- добавлять и удалять туры из избранного;
- видеть избранные туры в профиле;
- бронировать туры;
- выбирать дату и количество билетов;
- применять промокод;
- оплачивать бонусами при наличии баланса;
- смотреть свои покупки, транзакции и бонусы.

Не может:

- открывать `/admin`;
- создавать туры, отели, промокоды;
- начислять бонусы другим пользователям.

### partner

Партнер, который управляет своим контентом.

Может:

- входить в партнерскую/admin область;
- создавать и редактировать свои туры;
- создавать и редактировать свои отели;
- создавать промокоды для своих туров или отелей;
- смотреть профиль партнера.

Не должен:

- управлять чужими турами и отелями;
- начислять бонусы пользователям;
- управлять всеми пользователями;
- получать права admin.

### admin

Администратор платформы.

Может:

- открывать все admin-разделы;
- управлять пользователями;
- создавать и редактировать туры и отели;
- управлять партнерами;
- создавать общие и targeted промокоды;
- начислять бонусы пользователям;
- управлять баннерами, рекламой и контентом.

## Основные user flows

### Поиск тура

1. Пользователь открывает главную страницу.
2. Вводит название тура или выбирает даты.
3. Переходит на `/tours` с query-параметрами.
4. Сервер возвращает отфильтрованные и отсортированные туры.
5. Пользователь открывает карточку или смотрит точки на карте.

### Избранное

1. Guest нажимает heart на карточке тура.
2. Открывается login modal.
3. User нажимает heart.
4. Клиент отправляет toggle-запрос в API.
5. Тур появляется или исчезает на `/profile/favourites`.

### Бронирование тура

1. User открывает `/tours/:id`.
2. Выбирает доступную дату в календаре.
3. Выбирает количество билетов через `+` и `-`.
4. При необходимости вводит промокод.
5. Выбирает способ оплаты.
6. Подтверждает оплату.
7. Backend проверяет наличие мест и создает booking.

### Оплата бонусами

1. User имеет бонусный баланс.
2. На странице тура выбирает оплату бонусами.
3. Backend проверяет, хватает ли бонусов.
4. При успешной оплате бонусы списываются, бронь создается.

### Partner/admin создание промокода

1. Partner или admin открывает `/admin/promocodes`.
2. Указывает код, тип скидки, значение и период действия.
3. Partner выбирает только свои туры или отели.
4. Admin может создать общий промокод или привязать его к партнеру/туру/отелю.

### Admin начисляет бонусы

1. Admin открывает `/admin/bonuses`.
2. Выбирает пользователя.
3. Указывает количество бонусов и комментарий.
4. Backend добавляет бонусы и пишет wallet transaction.

## Manual QA checklist

### Запуск

- [ ] Backend запущен и отвечает на `GET /api/health`.
- [ ] Client запущен и открывается на `http://localhost:3000`.
- [ ] В `.env` клиента `NUXT_DEV_API_TARGET` смотрит на актуальный backend.
- [ ] В консоли браузера нет ошибок API base URL.

### Guest

- [ ] Главная страница открывается без авторизации.
- [ ] `/tours` и `/hotels` открываются без авторизации.
- [ ] Heart на `TourCard` открывает auth modal.
- [ ] Попытка бронирования открывает login modal.
- [ ] `/profile` редиректит или просит авторизацию.
- [ ] `/admin` недоступен.

### User

- [ ] Login проходит успешно.
- [ ] Heart добавляет тур в избранное.
- [ ] Повторный heart удаляет тур из избранного.
- [ ] `/profile/favourites` показывает реальные избранные туры.
- [ ] На странице тура доступны только даты с местами.
- [ ] `+` и `-` корректно меняют количество билетов.
- [ ] Итоговая сумма пересчитывается.
- [ ] Промокод применяет скидку.
- [ ] Оплата бонусами доступна только при достаточном балансе.

### Partner

- [ ] Partner login открывает admin layout.
- [ ] Partner видит только разрешенные разделы.
- [ ] Partner может создать тур.
- [ ] Partner может создать промокод для своего тура или отеля.
- [ ] Partner не может открыть `/admin/bonuses`.
- [ ] Partner не может управлять чужими турами.

### Admin

- [ ] Admin открывает `/admin`.
- [ ] Admin видит users, partners, tours, hotels, promocodes, bonuses.
- [ ] Создание промокода отправляет `POST /api/promocodes`.
- [ ] Новый промокод появляется в списке.
- [ ] Начисление бонусов отправляет `PATCH /api/users/:id/bonus`.
- [ ] Бонусы появляются в транзакциях пользователя.

### Regression

- [ ] Карта туров показывает метки.
- [ ] Yandex Maps грузится при наличии ключа.
- [ ] `UiInput`, `UiSelect`, `UiCalendar` очищаются reset-кнопкой.
- [ ] `UiClampText` раскрывает и скрывает описание без прыжков карточки.
- [ ] Loading отображается во время API-запросов.
